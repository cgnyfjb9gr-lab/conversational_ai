# Data Model: Agent Execution Tracing

**Feature**: `010-agent-tracing` | **Date**: 2026-11-07

This is a trace data model, not a database schema. Nothing is persisted by the application; spans are held in memory and exported to the configured backend. The names below are the contract used by tests, dashboards and alarm filters.

## Entities

### TurnTrace

One user turn's complete execution record. Represented by the root span.

| Field | Type | Required | Description |
|---|---|---|---|
| `trace_id` | string | yes | Generated by OpenTelemetry. Must be X-Ray-compatible in AWS mode. |
| `session_id` | string | no | The chat session from the backend; generated locally by the CLI. Attached as `session.id`. |
| `prompt_version` | string | yes | Value of `PROMPT_VERSION` at turn time. Attached as `prompt.version`. |
| `environment` | string | yes | `local`, `staging`, `prod`, etc. Resource attribute `deployment.environment`. |
| `service_name` | string | yes | `convai-wealth-agent`. Resource attribute `service.name`. |
| `started_at` | timestamp | yes | Root span start. |
| `ended_at` | timestamp | yes | Root span end. |
| `compliance_status` | `pass` \| `fail` | yes | Roll-up of all guardrail checks. |
| `compliance_failed_rules` | string | yes | Comma-separated failed rule ids; empty when none. |
| `compliance_check_count` | integer | yes | Number of checks recorded in the turn. |

**Relationships**:
- One `TurnTrace` has one root `ExecutionSpan` (`wealth_agent.turn`).
- One `TurnTrace` has one `ComplianceSummary`.
- One `TurnTrace` has zero or more `GuardrailCheck` records.
- One `TurnTrace` has one or more child `ExecutionSpan` records.

**Validation**:
- Exactly one root span per trace.
- `compliance_check_count` equals the number of `GuardrailCheck` records in the turn.
- `compliance_status=fail` if and only if at least one check has `result=fail`.
- `compliance_failed_rules` is the sorted, comma-separated set of failed rule ids.
- `session.id` is omitted when unknown; the CLI always supplies one.

### ExecutionSpan

A timed unit inside a turn trace.

| Field | Type | Required | Description |
|---|---|---|---|
| `span_id` | string | yes | OpenTelemetry span id. |
| `parent_span_id` | string | no | Parent span id; absent on the root. |
| `trace_id` | string | yes | Owning turn trace. |
| `name` | string | yes | `wealth_agent.turn`; Strands names: `invoke_agent <agent name>`, `execute_event_loop_cycle`, `chat`, `execute_tool <tool name>`. |
| `kind` | enum | yes | `internal` for all spans emitted by this feature and by Strands. Auto-instrumented HTTP spans may use other kinds. |
| `status` | `OK` \| `ERROR` | yes | `ERROR` only for unexpected infrastructure exceptions. A failed guardrail is not an error. |
| `started_at` | timestamp | yes | Start time. |
| `ended_at` | timestamp | yes | End time. |
| `attributes` | map | no | Span-specific attributes below. |
| `events` | list | no | Guardrail events and framework events. |

**Span-specific attributes**:

| Span | Attributes |
|---|---|
| `wealth_agent.turn` | `session.id`, `prompt.version`, `compliance_status`, `compliance_failed_rules`, `compliance_check_count` |
| `invoke_agent <name>` | Strands: `gen_ai.operation.name`, `gen_ai.agent.name`, `gen_ai.request.model`, `gen_ai.agent.tools`, `gen_ai.system_instructions`, token usage; plus `prompt.version`, `session.id` (via `trace_attributes`) |
| `execute_event_loop_cycle` | Strands: cycle id, input/output messages |
| `chat` | Strands: `gen_ai.request.model`, `gen_ai.input.messages`, `gen_ai.output.messages`, token usage |
| `execute_tool <name>` | Strands: `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.tool.status`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`, `prompt.version`, `session.id`; custom: `tool_ok`, `guardrail_rule_id`, `guardrail_result`, `guardrail_reason`, `guardrail_action` |

**Validation**:
- `wealth_agent.turn` has no parent when no auto-instrumentation wraps it; under `opentelemetry-instrument` an HTTP server span may be its parent.
- Every span other than the trace root has a parent in the same trace.
- Tool guardrail attributes only appear on `execute_tool` spans.
- `tool_ok` is a boolean and matches the handler's `ok` value.
- When content capture is disabled, no content attribute (see below) is present.

### GuardrailCheck

The result of one existing check.

| Field | Type | Required | Description |
|---|---|---|---|
| `rule_id` | enum | yes | `GR-TOOL-INPUT` or `GR-OUTPUT-DISCLAIMER`. |
| `result` | `pass` \| `fail` | yes | Outcome of the check. |
| `reason` | string | yes | Short, fixed or derived reason. No user content unless full capture is enabled. |
| `action` | enum | yes | `allow`, `return_error`, `append_disclaimer`. |
| `tool_name` | string | no | Present for `GR-TOOL-INPUT`. |
| `timestamp` | timestamp | yes | Event time. |

**Validation**:
- `rule_id` must be one of the two constants in this version.
- `GR-TOOL-INPUT` maps `ok=true` → `pass`/`allow`; `ok=false` → `fail`/`return_error`.
- `GR-OUTPUT-DISCLAIMER` maps "raw answer already contains disclaimer" → `pass`/`allow`; "code appended it" → `fail`/`append_disclaimer`.
- Reasons are short: for tool failures, the existing validation message; for disclaimer failures, `"model omitted disclaimer; appended by code"`.
- A check never raises into the caller.

### ComplianceSummary

Derived, not stored as a separate record. Written onto the root span.

| Field | Type | Description |
|---|---|---|
| `compliance_status` | `pass` \| `fail` | `fail` if any check failed, otherwise `pass`. |
| `compliance_failed_rules` | string | Comma-separated failed rule ids, sorted; empty string when none. |
| `compliance_check_count` | integer | Number of checks in the turn. |

**Validation**:
- Must be written before the root span ends.
- Must be computed from the turn's own collector, never from a global or previous turn.
- When no checks ran, `status=pass`, `failed_rules=""`, `count=0`.

### TracingConfiguration

Runtime configuration, not a span.

| Field | Type | Default | Description |
|---|---|---|---|
| `mode` | `off` \| `console` \| `adot` | `off` everywhere (library, tests, CLI, agent server); unknown value → `off` with a warning | Selects the export path. |
| `service_name` | string | `convai-wealth-agent` | Resource `service.name`. |
| `service_version` | string | package version or `0.1.0` | Resource `service.version`. |
| `environment` | string | `local` | Resource `deployment.environment`. |
| `capture_content` | boolean | `true` only when `environment=local` | Whether prompt/reply/tool content is exported. |
| `sample_ratio` | float | `1.0` | POC samples every turn. |
| `aws_region` | string | unset | Used to build the CloudWatch endpoint in the runbook. |

**Validation**:
- `environment != local` and `capture_content=true` → `TracingConfigError` at startup.
- `environment != local` and `capture_content=false` → metadata-only via Strands' redaction token.
- `mode=adot` and environment not set explicitly → `TracingConfigError` (fail closed).
- `OTEL_RESOURCE_ATTRIBUTES` and `DEPLOYMENT_ENVIRONMENT` both set and different → `TracingConfigError`.
- `mode=adot` → no local provider is created; ADOT owns the provider.
- `mode=off` → all helpers are no-ops.

## Trace lifecycle

```text
ask() starts
  -> create root span "wealth_agent.turn"
  -> set session.id, prompt.version (also on the agent's trace_attributes)
  -> bind a fresh TurnGuardrails collector
  -> call the agent
       -> Strands creates invoke_agent -> execute_event_loop_cycle -> chat / execute_tool spans
       -> each tool _safe() records GR-TOOL-INPUT on the active tool span
  -> apply disclaimer logic
  -> record GR-OUTPUT-DISCLAIMER on the root span
  -> compute and set compliance summary
  -> end root span
  -> unbind the collector
  -> return the answer unchanged
```

## Content-bearing attributes

These carry prompt, reply or tool content. In metadata-only mode Strands' own redaction replaces their values with its redaction marker (token `gen_ai_unredacted_attributes=` in `OTEL_SEMCONV_STABILITY_OPT_IN`):

- `gen_ai.system_instructions`
- `gen_ai.input.messages`
- `gen_ai.output.messages`
- `gen_ai.tool.call.arguments`
- `gen_ai.tool.call.result`

These names apply to the `gen_ai_latest_experimental` convention, which this feature requires. Under Strands' legacy convention the same content would be span events (`gen_ai.system.message`, `gen_ai.user.message`, `gen_ai.choice`, ...) and the redaction switch would not apply; the legacy convention is therefore not supported.

Content is exported only when `deployment.environment=local` and `capture_content=true`.

## Attribute naming

- **Standard/semantic attributes** use dotted names: `gen_ai.*`, `session.id`, `prompt.version`, `service.name`, `deployment.environment`.
- **Guardrail/compliance attributes** use flat underscore names: `guardrail_rule_id`, `guardrail_result`, `guardrail_reason`, `guardrail_action`, `tool_ok`, `compliance_status`, `compliance_failed_rules`, `compliance_check_count`.
- **Why flat for guardrails/compliance**: CloudWatch Logs metric filters and alarm definitions are simpler and less error-prone with flat keys. The dotted `gen_ai.*` attributes remain available for the GenAI views.

## State transitions

| From | Event | To |
|---|---|---|
| Turn started | root span created, collector bound | In progress |
| Tool returned `ok=true` | `GR-TOOL-INPUT` pass | In progress |
| Tool returned `ok=false` | `GR-TOOL-INPUT` fail | In progress |
| Agent returned raw answer with disclaimer | `GR-OUTPUT-DISCLAIMER` pass | In progress |
| Agent returned raw answer without disclaimer | `GR-OUTPUT-DISCLAIMER` fail + append | In progress |
| Summary written | root span ends | Complete |
| Exporter fails | warning logged | Complete; reply unchanged |
